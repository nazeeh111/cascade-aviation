# Forecast model card

CASCADE estimates the share of a selected airport's departures scheduled in the next two hours that will leave at least 15 minutes late or be cancelled. A cutoff is an hourly UTC timestamp. A row is one airport and cutoff, and the denominator is scheduled departures in that window. Metrics use windows with at least three scheduled departures. The same flight appears in overlapping adjacent two-hour windows, so interval metrics must not be summed into unique flights or daily impacts.

## Data and availability

The reporting year is 2024. Four hubs and four reporting carriers create a selected subnetwork, not a full US-system estimate. The feature pipeline is SQL in the warehouse. Model code consumes the resulting table as arrays; it does not replace the SQL investigation with dataframe analysis.

BTS publishes retrospective reports. The final reported schedule is treated as a proxy for the schedule known at each cutoff, because historical schedule revisions are unavailable. Actual departure events enter features only after their event timestamp plus a conservative one-hour reporting delay. NOAA observations also receive one hour of assumed latency. These assumptions support a historical replay; this release is not a live operational data integration. Missing observations, stale weather and overnight gaps remain explicit.

Model inputs include airport identity, seasonal hour/day/month, the upcoming scheduled workload, recently reported departure count/stress/delay, prior-day/prior-week and rolling recent rates, and latest available wind, visibility, temperature, and observation age. The network variants additionally consume a weighted neighbor stress measure based on earlier schedules. No future realized weather, delay-cause fields, future tail assignments, cancellation outcomes, or arrival outcomes are model features. The exact field list and source code hashes are saved with each run.

## Comparisons

1. Seasonal baseline: weighted training mean for airport, hour and day of week, with a training-only global fallback.
2. Rolling baseline: the warehouse's strictly backward-looking rolling reported-departure stress.
3. Tabular model: pooled histogram gradient boosting with categorical airport identity, recent state, weather and schedule features.
4. Network tabular ablation: the same estimator with the additional neighbor stress feature.
5. Temporal graph residual: a compact model adding a regularized residual correction to the tabular prediction. Its inputs combine lagged local state and schedule-weighted neighbor state. This is graph aggregation followed by a linear residual model, not a deep graph neural network. The residual model learns only from later inner-block predictions generated by a base model fitted on an earlier block.

The compact graph residual directly tests whether a small graph-aware correction helps. PyTorch Geometric is not needed for this bounded four-node model; larger graph architectures would need evidence that their additional complexity earns its cost. No graph superiority is assumed.

## Evaluation protocol

May, July and September are rolling-origin evaluation months, each trained only on earlier months with fixed predeclared parameters. The final test is November–December. Hyperparameters for the final model are selected using October 1–15 after training January–September. The chosen models are then fitted using January–October 15. October 16–31 supplies separate calibration residuals. Every training/validation/calibration/test boundary purges targets within two hours of the next partition, so labels cannot cross a boundary. Training, tuning and calibration partitions also require target labels to be available before their ending boundary. A delayed flight can finish after the two-hour window, so a window purge alone is insufficient. Departure labels use actual departure plus one hour. BTS supplies no cancellation-announcement time; cancellation labels use a declared conservative proxy of scheduled departure plus 24 hours. This is an assumption, not archived operational evidence. Rows whose labels are still unavailable at a fit, tuning or calibration boundary are excluded from those partitions. Final and rolling-origin test scoring uses eventual observed labels, so severe late outcomes are retained. The full target window must still fit the declared scoring period. No random train/test split is used.

The tuning set chooses between two predeclared tree-complexity settings. It does not select by final holdout performance. The scenario policy uses the predeclared tabular model even if a different model happens to perform better in the final test.

The run reports MAE and RMSE of disruption share, flight-denominator-weighted MAE, signed bias, ten-bin weighted calibration error, and severe-event recall/precision at a fixed 40% disruption threshold. A severe event is an airport interval, not an individual flight. Per-model and model-bundle fit/predict runtimes are measured. Graph-residual runtime includes its base tabular prediction/training requirement; residual fitting also includes the earlier inner base model. Bundle runtime must not be mistaken for per-model runtime. A paired airport-day bootstrap compares network and non-network tabular MAE, but cross-airport correlations limit its interpretation. This is a predictive comparison, not a causal estimate of network effects.

Symmetric prediction intervals use the 90th percentile of absolute residuals on the separate calibration period, clipped to [0,1]. Temporal drift can invalidate nominal 90% coverage, so actual test coverage and interval width are reported. A calibrated disruption share is not a calibrated probability of a severe airport event.

## Reproduction and limits

Run `cascade.forecast.run(connection, root)` after building `airport_hour_features`. It writes `artifacts/metrics.json`, `model_run.json`, `predictions.parquet` and the trusted local `forecast.joblib`. The input table digest, query, split dates, features, parameter search and package versions are retained in the run record.

A small real-data quickstart exercises ingestion/warehouse/SQL only. It cannot support annual chronological evaluation; the full-year build is required for the reported model comparison. Actual metrics are generated by the run, never copied into this document as invented examples.

The network-feature ablation changes mean airport-day MAE by +0.010 percentage points; its descriptive 95% airport-day bootstrap interval is [-0.095, 0.110] pp. It does **not demonstrate an MAE improvement** over the tabular model on this holdout. The graph residual has a slightly lower point MAE but higher RMSE than tabular; this small difference does not establish general graph-model superiority.

The tabular model recalls 51.9% of severe airport intervals. Its nominal 90% interval covers only 81.5% of test outcomes, so the interval is **undercovered under temporal shift**. A low binned mean-rate calibration error does not repair this interval undercoverage or imply reliable severe-event probabilities. These limitations remain part of the release.
